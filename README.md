# АС «Реестр ГИС» — управление доступом пользователей

Практический кейс по системному и бизнес-анализу, выполненный после собеседования на позицию бизнес-аналитика.

Задача — проработать функциональность управления пользователями и уровнями доступа в автоматизированной системе «Реестр ГИС» и подготовить постановку задачи для разработки.

## Что было сделано

В рамках работы:

- проанализированы исходные требования;
- сформализованы функциональные и нефункциональные требования;
- описаны пользовательские роли и сценарии;
- определены бизнес-правила и ограничения;
- подготовлены критерии приёмки и тестовые наборы;
- описаны поля и правила их валидации;
- разработана статусная модель;
- описан бизнес-процесс управления пользователями;
- проработаны алгоритмы и интеграционные зависимости;
- подготовлена матрица трассировки требований;
- разработаны макеты интерфейсов в Figma;
- подготовлено описание автоматизируемых функций по ГОСТ 34.

В постановке сформировано 22 функциональных требования и 32 критерия приёмки.

## Основная функциональность

Проработаны сценарии:

- просмотр списка пользователей;
- поиск по ФИО и электронной почте;
- фильтрация по организациям и ролям;
- добавление и редактирование пользователей;
- назначение ролей;
- ограничение доступа по сроку;
- регистрация пользователей с одинаковым ФИО;
- проверка прав администратора;
- валидация данных и обработка ошибок;
- защита от конфликтов при одновременном редактировании.

## Документы

### Постановка задачи разработчику

Основной аналитический документ проекта.

Содержит требования, пользовательские сценарии, критерии приёмки, описание полей, статусную модель, бизнес-процесс, алгоритмы, интеграции и матрицу трассировки.

### Описание автоматизируемых функций

Документ П3 для комплекса задач «Управление уровнем доступа пользователей».

Подготовлен с учётом ГОСТ 34.201-2020 и ГОСТ 34.601-90. ГОСТ 34.602-2020 использовался как методическая основа при формулировании требований.
